# Cold test 2: a new buyer with only the README and the signed binary

Tester: read README.md only, then ran `dist/shotfleet` (arm64, 0.1.0, licence gate off) in a clean environment
(`env -i PATH=/usr/bin:/bin:/opt/homebrew/bin HOME=$HOME`, `SHOTFLEET_OCR` set to `tools/ocr_tesseract.py`).
Scratch folder: `.../scratchpad/coldtest2`. No simulator or emulator was booted, no Maestro ran. For config
errors that only surface after the Maestro check, I put a stub `maestro` (prints `2.0.0`) on PATH and set
`DEVELOPER_DIR=/nonexistent` so no simulator could boot. Real apps used: Kuokka.app, composeApp-release.apk,
Crossfit Tracker.app (iPhone-only), screenshots from `site/public/img` (360x782 thumbnails, so every iOS size
check fails; that noise is mine, not a bug).

Two environment events: `dist/` was emptied and rebuilt by someone else mid-test (binary missing for about 30 s,
exit 127), and Kuokka.app vanished from DerivedData for a moment. Not product findings.

## README read as a buyer

- **Missing prerequisites**: Java 17+ (Maestro needs it, doctor does not check it, README never says); Homebrew (used by the `ln -s` line); Xcode with an iOS 26 runtime and a **Debug-iphonesimulator** build (the README says "simulator build" only in a code comment, and a buyer's first build is usually a device or archive build); Android: an AVD with API 33+ must already exist (does shotfleet create it? README says nothing); disk and time cost (a run boots up to 4 simulators).
- **Order**: `shotfleet doctor` comes after the install line but nothing says to fix its MISSING lines before `init`; step 2 `run --locales en` is the first time anything boots, but it is not said it needs a built app and Maestro already working.
- **Contradictions**: (1) Quickstart runs `init` with both an .app and an APK, which writes a config with both platforms, so output goes to `out-ios` / `out-android`, yet step 4 says "Review `out/index.html`" and step 5 says `export out`. A buyer following the quickstart literally has no `out/`. The parenthesis in step 5 hides this. (2) `shotfleet.py` vs "one signed binary" vs "Needs Python 3.11 or newer" (see 2). (3) "no Python or Swift needed" vs doctor's `swiftc` line. (4) The Config comment says out defaults to "out", which is only true for a single-platform file. (5) `<out>-ipad` appears as `out-ipad`, `<out>-ipad` and (when both platforms) `out-ios-ipad`; the buyer is never shown the final names. (No `ios/out` path appears in the README; all outputs are `out`, `out-ios`, `out-android`, `-ipad` suffixes, relative to where is not stated: config folder or current folder?)
- **Claims not backed by what I saw**: "found a real problem on CrossfitTracker" and "onboarding page whose Next button was unreachable" cannot be reproduced by a buyer (no sample data shipped); the CI recipe is marked untested (good, honest). "Flutter and React Native... tested with sample files" is honest.
- **Words a buyer may not know**: Maestro (linked once, fine), `fastlane deliver` / `supply` (assumed), "sharded Maestro run", "SystemUI demo mode", "TCC.framework", "lproj", "locale" vs "language" used interchangeably, "collision", "store codes", "anchor that step with `below:`" (never explained; `below:` is a Maestro selector, no example).
- **Length and focus**: the buyer's first 45 lines are about `check`, the product's second feature; `run` appears at line 46. The "Install and licence" section (the only place the price/licence appears) is at line 89, after Config-adjacent material. A buyer looking for "how do I get it" must read half the page.

## Top 8 changes, by buyers saved from giving up

1. **Notarize the binary** (finding 1). Everyone who downloads it sees a Gatekeeper block; many will stop there. Affects 100% of buyers.
2. **Fix the install story in the README** (finding 2): binary, where to download, where to put it, remove `shotfleet.py`, `brew --prefix` and "Python 3.11" from the buyer path. Affects 100%; today the first command of the Quickstart cannot work.
3. **Make the quickstart's `out` path match what `init` writes** (README contradiction 1): either `init` with two builds still writes `out`-based names the steps use, or the steps say `out-ios`/`out-android` when both builds were given. Hits every buyer who follows the quickstart literally, at step 4.
4. **Reject unknown config keys and validate value types** (13, 14): `ipd = true` and `parallel = "four"` currently cost a multi-minute run or show a traceback.
5. **List Maestro's real prerequisites and make `doctor` check them** (6): Java, the Debug-iphonesimulator build, an API 33+ AVD, then a closing "next:" line. The buyer's second step otherwise ends in a Maestro Java error doctor said was fine.
6. **Say how to get a licence key and the website URL, and that activation needs internet** (23): the error message and README currently point to "the site" with no address.
7. **Fix `check` on a standard fastlane folder with both platforms** (20): one README sentence or accept both; it fails the headline example for most teams that publish on both stores.
8. **Make the `--locales` validation use the app's own languages** (15) **and make `init` not lie when it keeps an existing config** (9): both let a buyer run a long capture for the wrong languages or the wrong app.

Smaller items worth batching: portable report HTML and per-cell reasons (19), validate config before checking tools (17), `doctor` exit code (4), `sysctl` absolute path (7), startup time 2.5 s (3).
