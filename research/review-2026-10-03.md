## Ranked findings

### 1. HIGH (CONFIRMED by reading and by repro): the licence accepts keys it shouldn't, and anyone can redirect it

`shotfleet.py:1901,1905,1941-1957,1971-1997`

- **Defect 1:** `cmd_activate` and `require_licence` accept ANY valid Lemon Squeezy licence key. They check only `activated` / `valid` and never compare `meta.store_id` or `meta.product_id` in the response with shotfleet's own. Lemon Squeezy's licence endpoints are not scoped to one store.
  - **Scenario:** a key from any other seller's Lemon Squeezy product (a $1 plugin, say) runs `shotfleet activate <that key>` and gets a full `run` and `export`.
  - **Fix:** add `LS_STORE_ID` / `LS_PRODUCT_ID` constants, and in both activate and validate require `r.get("meta", {}).get("product_id") == LS_PRODUCT_ID`.
- **Defect 2:** `LICENCE_API` and `GUMROAD_API` are read from the env vars `SHOTFLEET_LICENCE_API` and `SHOTFLEET_GUMROAD_API` in released builds too.
  - **Scenario:** `SHOTFLEET_LICENCE_API=http://127.0.0.1:8000 shotfleet activate x`, against a fake server that returns `{"activated":true,"instance":{"id":"1"}}`, passes without buying anything. I confirmed the vars are honoured at import (t6.py, B2).
  - **Fix:** only honour the overrides when `not getattr(sys, "frozen", False)`.
- **Defect 3:** with `SHOTFLEET_KEY` set, `require_licence` does `except OSError: return`.
  - **Scenario:** `SHOTFLEET_KEY=anything` with no network, or `SHOTFLEET_LICENCE_API=http://127.0.0.1:9`, passes. Confirmed in t6.py, B. The "CI shouldn't fail" intent turns into a bypass.
  - **Fix:** in the env-key path, treat unreachable as OK only if a previous successful check is cached. For example, reuse `LICENCE_FILE`'s `checked` within `LICENCE_OFFLINE_DAYS`, and otherwise fail.
- **Defect 4:** the local licence file is forgeable. `{"key":"x","instance":"y","checked":<future time>}` makes `age` negative, so it is never revalidated (CONFIRMED, t6.py, C).
  - **Fix:** clamp with `age = max(0, ...)` and reject `checked > time.time() + 86400`. A copied file still passes on any Mac, so treat this as friction, not security.
- **Related, LOW:**
  - A corrupt `licence.json` raises a raw `JSONDecodeError`, which the dispatcher prints as "shotfleet: Expecting value ..." (CONFIRMED, t6.py, D). Wrap the read and ask the user to re-activate.
  - `GUMROAD_PRODUCT_ID = ""` until go-live.sh runs. Every Gumroad key fails until then, so go-live.sh must run before any build ships.

### 2. MEDIUM-HIGH (CONFIRMED): the Tesseract substring bonus lets a wrong-language screenshot pass

`shotfleet.py:1248-1251` (`judge_screen`, external OCR branch)

- **Defect:** `v in text` counts a locale's string even when it sits inside a longer word, with only a length-5 floor.
- **Repro (t5.py):**

  | Locale | Strings |
  |---|---|
  | `en` | Start, History, Settings |
  | `de` | Starten, Verlauf, Einstellungen |

  - A German screen ("Starten\nVerlauf") in the `en` listing, via Tesseract (`ocr:"external"`), returns `('en', None)`, a PASS.
  - The same text via Vision returns `('de', "shows de strings (2 lines) more than en (0)")`.
  - The `en` string "Start" is found inside "Starten". The score becomes de=2, en=1, and the gap of 1 is below the "2 when score<3" threshold.
- **Impact:** with auto-Tesseract now used for Greek, Hebrew, Indic and similar scripts, and for all languages when macOS OCR is stuck, wrong-language screenshots slip through. The effect is worst in closely related languages (de/nl/da/sv, es/pt/it).
- **Fix:** match on word boundaries, e.g. `re.search(rf"(?<!\w){re.escape(v)}(?!\w)", text)`, or require the value to start and end at a `|` or whitespace boundary of the joined lines. Optionally also require `len(v) >= 6`.

### 3. MEDIUM (CONFIRMED): app-text (`.texts.json`) screens lose language detection, and an empty tree fails instead of falling back to OCR

`shotfleet.py:1359-1366` (`screen_text`), `1260-1280` (`judge_screen`), and `1475-1478`

- **Defect A:** `screen_text` returns `lang: None, langs: {}`. When fewer than 2 lines match any string table (`best < 2`), `judge_screen` falls through to `return lp, None`, always a pass.
  - **Repro (t4.py):** a screen with only user content plus one table string ("Welcome back, Sam / Your streak is 4 days / Timer") in the `de` listing gives `('de', None)`. The OCR-shaped dict for the same text gives `('en', "text looks like 'en', expected 'de'")`.
  - **Impact:** an English screen in a German listing passes if it is mostly dynamic or user content.
  - **Fix:** run `NLLanguageRecognizer` on texts that don't match any table, or mark app-text results as "weak" and fall back to Vision OCR when `best < 2`. For example, in `cmd_check` treat `screen_text(...)` as usable only if it scores >= 2 against some table. Otherwise OCR it too.
- **Defect B:** `screen_text` returns a dict (truthy) even for `[]`, so `chars == 0` leads to "no text found (blank or still loading?)" (CONFIRMED, t4.py case 2). An empty accessibility tree is plausible: the app is not the foreground app, the driver is mid-transition, or the view is a Metal/Canvas/game surface.
  - **Impact:** a good screenshot fails and OCR is never tried.
  - **Fix:** `if not text.strip(): return None`.
- **Defect C:** a half-written or corrupt `.texts.json` makes `screen_text` raise `JSONDecodeError`, which aborts the whole `check` with exit 2 (CONFIRMED, t4.py case 4). Wrap `json.loads` in `try/except ValueError: return None`. Write the file atomically (`write_text` to `.tmp`, then `os.replace`).

### 4. MEDIUM (TRACED): `capture_texts` can attach the wrong screen's text to a screenshot

`shotfleet.py:717-740`, `641-655`

- **Defect:** the reader is one thread. It handles every simulator's new screenshot sequentially, each with a 5 s HTTP timeout, and `ios_screen_texts` just reads the current tree. Nothing ties the tree to the screenshot.
- **Scenario:** with 4 sims, 4 screenshots appear within a second. Reading the 3rd and 4th sims' trees takes 3 or more reads (each 0.2-3 s on a heavy SwiftUI screen), longer than the 1.5 s pause. Maestro has moved on, so screenshot N is paired with the text of screen N+1.
  - Since texts are preferred over OCR, an untranslated screen N can pass on the strength of another screen's German strings.
- **Related (CONFIRMED, t1.py):** `screenshot_ends` only inserts the pause for the bare scalar form, or the map form where `path:` is the last key. For a map-form `takeScreenshot` with other keys (`cropOn:`, `path:` first or last), no pause is inserted. For the cropOn variant the reader still fires on the new PNG, but the flow doesn't wait, so the read is almost always of a later screen.
- **Fix:** one reader thread per port, or a `ThreadPoolExecutor` keyed by port, and fire the read in the same poll that sees the PNG. For the map form, insert the pause after the whole step (look ahead to the end of the indented block). Optionally re-read the tree after 300 ms and discard it if it changed.
- **Also (TRACED):** `done` is keyed by path and the first read wins. If a flow re-takes the same name (`takeScreenshot: 02` twice, in a `repeat`, say), the png is overwritten and its texts stay stale.
- **Also (CONFIRMED, t7.py):** the reader thread dies on non-OSError/ValueError exceptions. A malformed response (`http.client.BadStatusLine`, `IncompleteRead`) or a tree that is a JSON list (`AttributeError`) kills it, with a traceback on stderr. Every later screenshot silently goes to OCR. Catch `Exception` per png, and guard `log.read_text` (an `OSError` there also kills the thread).
- **Perf (LOW):** each 0.2 s tick re-reads and regexes every `maestro.log` in full. Track file size or offset and read only the new bytes.

### 5. MEDIUM (CONFIRMED): the multi-device iOS simulator pool cleanup deletes other devices' simulators

`shotfleet.py:665-672` (`make_pool`), called from `ios_run` with prefix `shotfleet-<slug>`

- **Defect:** `d["name"].startswith(prefix + "-") and d["name"] not in by_name` deletes any same-runtime sim whose name starts with the prefix but doesn't match the current device type.
  - `device_types = ["iPhone 17", "iPhone 17 Pro Max"]` (or 17 Pro and 17 Pro Max): the `shotfleet-iphone-17` pool deletes `shotfleet-iphone-17-pro-max-*` (repro t2.py #3: `simctl delete U1`).
  - After any multi-device run, a plain single-device run (prefix `shotfleet`) deletes every `shotfleet-<slug>-N` sim (t2.py #3b: deleted U2).
  - Impact: the cache is thrown away and recreated on every run (slow). If one of those sims is booted and in use, `simctl delete` fails silently (the return code isn't checked), leaving a stale name clash.
- **Fix:** match `re.fullmatch(re.escape(prefix) + r"-\d+", name)`.
- **Related, TRACED:** nothing shuts down the first device's simulators before the second device's pool boots. `OUR_SIMS` is only shut down in `main_cmd`'s `finally`, and `fit_parallel` checks pressure before booting more. A 2-device run therefore holds 2N booted sims. Shut down `pool` at the end of `ios_run`, in a `finally` (it also leaks on a `Fail` mid-run in the MCP server, which never exits).

### 6. MEDIUM (CONFIRMED): a stale `out/run.json` hides a multi-device run

`shotfleet.py:1750-1753` (`device_runs`), used by `ipad_set_missing`, `cmd_export` and the `check` dispatch

- **Defect:** `device_runs` returns `[]` whenever `out/run.json` exists (t2.py #2).
- **Scenario:** the user previously ran a single-device config (leaving `out/run.json`, `out/raw`), then adds `device_types`. The device runs go to `out/<slug>/`, but:
  - `ipad_set_missing(out)` finds no subs and returns 0, silently skipping the iPad check.
  - `shotfleet export out` exports the old single-device run, not the new iPhone and iPad sets.
  - `shotfleet check out` re-checks the old run.
- **Fix:** in `cmd_run` multi-device, delete the parent's `run.json`, `check.json`, `raw/` and `.work` first. Or have `device_runs` prefer subfolders when any exist.
- **Related (TRACED):** `--report` is silently ignored in the multi-device `check` branch (line 2030 passes no `report_dir`).
- **Related (TRACED):** `export` for a multi-device run does not enforce the iPad 13" requirement. `ipad_set_missing` only affects the exit code of `run` and `check` and is not recorded in any `check.json`, whereas the single-run rule marks every listing bad.
  - A multi-device run with iPhone only (app runs on iPad) exports without complaint. Persist that problem into each `check.json`, or have `cmd_export` call `ipad_set_missing` on the parent.
- **Related (LOW, TRACED):** `shotfleet check out/<slug>` directly on one sub-run applies the iPad rule (`ipad_rule=True`) to the iPhone sub-run and flags every listing.

### 7. MEDIUM (CONFIRMED): a tablet-only Play folder given as `metadata/android` is checked with App Store rules

`shotfleet.py:1448` (`android = any(...phoneScreenshots)` fallback)

- **Defect:** the fallback only looks for `phoneScreenshots`, so a folder holding only `*/images/tenInchScreenshots` or `sevenInchScreenshots` is judged as iOS.
- **Repro (t3.py):** `check metadata/android` with only tablet shots reports "360x640 isn't an App Store screenshot size" for every file. With real 1440x2560 tablet PNGs it is the same, because `apple_class` is None. The same folder with a `phoneScreenshots` set is fine.
- **Impact:** tablet sets that were passed this way produce 100% false store-rule failures, unless `--app x.apk` is given. The `play_folders` branch in `main_dispatch` already detects them.
- **Fix:** in that fallback use `any(folder.glob(f"*/images/{k}") for k in PLAY_FOLDERS)`. Or pass `android=True` from the play_folders branch.

### 8. MEDIUM (TRACED, pre-existing pattern but now in the options path): nested `launchApp` is rewritten at column 0 and breaks the YAML

`shotfleet.py:606-639` (`launch`, `localize_flow`)

- **Repro (t1.py):**
  - A `- launchApp:` inside `- runFlow: commands:` is emitted as `- launchApp:` at column 0, between the `commands:` line and `- tapOn: Y`.
  - The original `commands:` list is left empty, and the following `- tapOn` loses its parent (YAML invalid or misparsed).
- **Scenario:** any `repeat`, `runFlow` or `when` that relaunches the app; the new block-option support makes this more likely.
- **Fix:** keep `m.group(1)` as the indent and re-indent the generated lines. Or reject nested launchApp with a clear ValueError ("launchApp must be a top-level step").

### 9. MEDIUM (TRACED): the MCP `check` bypasses the dispatch logic and can return stale or crashing results

`shotfleet.py:1859-1875` (`mcp_call`)

- **Defect A:** missing required args raise `KeyError`, which isn't in the caught tuple (CONFIRMED, t4.py: `mcp_call("check", {})` raises `KeyError 'folder'`). `cmd_mcp` has no try/except around `mcp_call`, so the whole MCP server dies on one malformed call.
  - **Fix:** wrap the body in `except Exception as e: return f"{type(e).__name__}: {e}", True`. Validate the args first.
- **Defect B:** `LAST_REPORT` is global and stale. `ios_run` and `android_run` return 1 early ("no screenshots were captured") without calling `cmd_check`, and in multi-device runs only the last device's report is kept. `mcp_call` then returns the previous `check`'s report with the failing exit code.
  - **Fix:** set `LAST_REPORT = None` at the start of each `mcp_call`.
- **Defect C:** MCP `check` doesn't go through `main_dispatch`, so Play tablet folders (only phoneScreenshots are looked at, the tablet set is silently skipped), multi-device runs ("no screenshots found"), `ocr_command` and the iPad cross-check are all skipped. Factor `main_dispatch`'s check branch into `check_any(folder, ...)` and use it in both.

### 10. LOW-MEDIUM (TRACED): Tesseract fallback edge cases

`shotfleet.py:1450-1470`, `1391-1405`

- **Defect A:** when macOS OCR is stuck (`use_vision=False`) and `ocr_command` was set to `TESSERACT_COMMAND`, `auto` is False. The `tesseract_code(...) in tesseract_languages()` filter is therefore skipped, and a missing language pack makes `external_ocr` raise `Fail("--ocr-command failed ... Failed loading language")` for the whole check. The message says "--ocr-command", although the user supplied none. Fix: compute `auto` before reassigning `ocr_command`, so the language filter still applies and unavailable languages degrade to "not read".
- **Defect B:** the stuck-ANE fallback is decided only once, in `warm_up_ocr`. If macOS OCR hangs later (`read_text` raises "hung twice"), the whole check aborts with no Tesseract fallback, although the README says `check` switches. Catch the RuntimeError from `read_text`, set `use_vision=False`, and redo those PNGs with Tesseract.
- **Defect C:** `a.format(...)` in `external_ocr` raises `KeyError` / `IndexError` on an unknown or stray `{...}` placeholder in a user's `--ocr-command`, which is a traceback. Catch it and raise `Fail("unknown placeholder {x}; use {image}, {lang}, {tesseract}")`.
- **Defect D:** `tesseract_languages` assumes the header is the first line of `stdout + stderr`. This is OK for Tesseract 5 (Homebrew) but on 4.x, where the header is on stderr, the first language is dropped.

### 11. LOW (TRACED): remaining items

- **Gumroad activation counting** (`1941-1950`):
  - `increment_uses_count=true` is counted on every `activate`, including a re-activate on the same Mac, a reinstall, and a failed `uses > MAX_MACS` attempt.
  - `deactivate` can't decrement. A user who activates 3 times on the same Mac is then locked out and told to email.
  - Nothing is bound to the machine, so copying `licence.json` bypasses the 3-Mac limit.
  - `SHOTFLEET_KEY` is documented as using no slot, so one key can run in unlimited CI jobs. Say so in the README or limit the key to N distinct hostnames.
- **System dialog apostrophe** (`514-516`): `"Don't Allow"` (ASCII) in a flow is not rewritten to the curly `"Don’t Allow"` that iOS and `SYSTEM_BUTTONS` use. `tr` returns `None` and leaves the ASCII text, so the tap may miss. Return `yaml_single_quote(text.replace("'", "’"))` when `system` and no keys.
- **README vs code:**
  - "iOS runs aren't affected: they read the app's own text" is true only if every screenshot got a `.texts.json`. Otherwise warm-up and OCR still apply, and `readable_languages()` (`ocr --langs`, no timeout) runs even then.
  - The README config section doesn't mention that `--report` is ignored for multi-device `check`.
  - `{tesseract_with_english}` is undocumented.
  - The README Devices row is still phone-only (1080x1920).
- **`latest_release`** treats any difference from `VERSION` as "is out", including a dev build newer than the release.
- **`doctor` and MCP `doctor`** call the shotfleet worker every run (5 s timeout). Fine, but document it in the privacy page.

- Per-locale `raw/<lp>` is cleared on retry, so stale `.texts.json` from attempt 1 is not reused.
