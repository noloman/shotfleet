What’s new

What changed for you in each release, newest first.

0.1.8, 2026-10-08

  • scrollUntilVisible with a plain text (element: "Settings") is now translated, like the object form. Before, the plain string stayed in English, so the step failed in every other language.
  • Before each takeScreenshot, run waits up to one second for the screen to stop moving, so a sliding sheet or a splash on its way out is less likely to end up in the picture. settle_ms in the config changes the time, and 0 turns it off. An app that holds one splash image for several seconds still needs a wait for a text on its first real screen.
  • Ask for zh-Hans on an Android app that ships zh-CN and run now uses zh-CN and says so, instead of telling you the app has none of your languages. zh-Hant and zh-TW work the same way, and so do pt and pt-BR. When two codes would fit, it doesn’t guess: it names the ones the app has.
  • A text selector that is a regex, or that comes from a format string like %@ on %@, can’t be translated. run now says so by name before it starts and suggests an id: or a label the app translates. Before, such a flow passed in English and failed in every other language with nothing said.
  • When a language fails, the failure screenshot is kept in out/failures/ and named in the message, also after a failed retry. “iOS driver not ready in time” on a simulator’s first boot counts as a device failure now, so it is retried once.
  • Two causes that used to fail with no hint now get a name: a splash screen that never hides (on Android) and a second Maestro job using port 7001. I tested these messages with fakes, not yet on a device.
  • check --app on a Flutter build tells you to pass --strings 'lib/l10n/*.arb', and --strings together with --app now works. On the parent folder of a multi-device run, a missing iPad set shows as missing and the exit code agrees with the problem count.
  • You can add key = "benchmarks_title" to an [expect.<screenshot>] table. check then needs the app’s own text for that string key, in the screenshot’s language, to be on screen, which catches a green run that captured the wrong screen. Nothing changes unless you add it.
  • doctor says which iOS runtime run will use, and why when a newer one is skipped. On Android with a Maestro older than 2.7.0, run says that check will read the text by OCR and suggests Maestro 2.11.0.

0.1.7, 2026-10-08

  • check now ends with a store coverage table: one row per language, one column per device class (App Store: iPhone 6.9", iPhone 6.5", iPad 13"; Google Play: phone, 7" tablet, 10" tablet), each cell ok, missing, too many or wrong size. It is also in index.html and check.json, and it changes no exit code.
  • check --compare <earlier folder> lists, per language and screen, what is new, removed or changed since an earlier shotfleet or fastlane folder. It is a report, and it doesn’t read any text.
  • export --print-upload prints the fastlane deliver or fastlane supply command that uploads what you exported. It only prints it: shotfleet still never uploads. The docs now show the asc screenshots upload route too.
  • run skips iOS 27.0 simulators unless you ask for them: they froze at boot in some of my runs. With no runtime in the config it uses the newest other one you have installed and says which, and why, in one line. A runtime you set is always used, and doctor warns if 27.0 is the only one installed.
  • When the Mac is very busy (swap almost full, critical memory pressure, or a load far above the number of cores), run says so once, in plain words, and suggests fewer parallel devices. Listing, creating and deleting simulators no longer wait forever: after a time limit they say the Mac is probably too busy.
  • run --retry-failed reruns only the languages that failed in the last run of that config. The ones that passed stay as they were. And run now retries a language by itself once, only when the simulator or emulator failed or the screenshot came out blank (the app painted its first frame late), not when your flow or app failed, because that would fail the same way again; it tells you which languages it didn’t retry.
  • Smaller: export hooks get SHOTFLEET_PLATFORM on iOS too; over MCP the run summary says when the free tier cut the languages; the Linux build no longer warns about a missing release date; the guides have an Atom feed.

0.1.6, 2026-10-06

  • New in 0.1.6, on iOS: run can run your own XCUITest screenshot tests (XCTAttachment or fastlane’s SnapshotHelper) instead of a Maestro flow, on several simulators at once, one language each, and then checks what they saved. For that you need neither Maestro nor Java. I tried the idea by hand first, and the finished feature then passed its device test on iOS 26.4 simulators. The docs show how to set it up.
  • Over MCP, run now refuses a config with a [capture] build, [ios] simctl or [android] shell commands unless you pass hooks: true, the same opt-in as for [hooks]. check over MCP no longer takes ocr_command; use --ocr-command in your terminal.
  • check understands fastlane supply’s file names, like 1_de-DE.png. Before, it said every language was missing every other language’s screenshots. On a real Google Play set in 15 languages, 15 false “missing” lines are gone.
  • A Russian screen with English job titles in it is no longer called Kazakh when the app’s own Russian strings match it. A Ukrainian screen in the Russian folder is still caught.
  • When a language fails, run now says where it stopped: the step, the path to the failure screenshot, and up to 12 texts that were on that screen.
  • iPad in landscape: when Maestro taps at the portrait position and misses, run says so in one line and tells you what to do instead.
  • The “this Mac was short of memory” note only shows up when a failure really looks like that, not on every failed flow.
  • From 0.1.6, a key can be activated 5 times (0.1.5 and earlier stop at 3): use it on up to 3 of your Macs, and the spare activations cover reinstalls. If you run out, email hello@shotfleet.com for a reset.
  • In CI, a SHOTFLEET_KEY that is refused or can’t be checked now stops run with exit 2, instead of quietly capturing 2 languages. With Gumroad unreachable, a key only counts on a machine where it passed a check in the last 30 days; on hosted runners, cache ~/Library/Application Support/shotfleet/ci-checked.json between jobs.
  • “A year of updates” now means exactly that: your key covers every shotfleet version released within a year of your purchase. A version that comes out later runs as the free tier and says which versions your key covers; the versions you have keep working. If you bought in October 2026, every version released until October 2027 is covered.

0.1.5, 2026-10-06

Works with what you already use

  • Already use fastlane snapshot or screengrab? check now works on those screenshots, no Maestro needed. It ignores the timestamp screengrab adds to every file name, so it no longer says every language is missing screens. The docs have a ready-made fastlane lane that stops before the upload when check finds a problem.
  • Paparazzi, Roborazzi or Compose preview renders: copy each language into its own folder, then run check on them. The docs show a short loop that does the copying. I haven’t tried it on a real Paparazzi project yet.
  • Homebrew: brew install noloman/tap/shotfleet installs the same signed build. Homebrew doesn’t install Maestro or Java, but shotfleet doctor --fix does. When a new version is out, doctor tells you to run brew upgrade.

More reliable on a busy Mac

  • You never need to restart your Mac when macOS text recognition is busy. check waits for it up to 8 minutes and then finishes anyway: it still checks sizes and missing screens, and it marks the screens it couldn’t read as “not verified”. Run it again later, or install Tesseract. Add --strict if unread screens should fail the check.
  • No system banners over your screenshots. On iOS, shotfleet tells each simulator right after boot that the “Ready for Apple Intelligence” banner was already shown. On Android it turns off pop-up notification banners during the run. I couldn’t make that iOS banner show up in a test yet, so I can’t prove this part works. As a backup, check now flags the banner at the top of a screenshot when it reads the pixels (Android, or screenshots you bring yourself).

Clearer results

  • check picks the right store by itself, from fastlane’s folder layout, your app build or the screenshot sizes. A plain folder of Android screenshots no longer gets judged by App Store sizes. Without --app, it also finds your app build in your project and tells you which one it used.
  • The HTML report works better with screen readers. Every screenshot has alt text with its language, screen and verdict, and problems are marked in words, not only with a red border.
  • The memory warning now says how many devices your run really uses. Before, it could say 4 when shotfleet had already cut the run to 2.

0.1.4, 2026-10-06

  • For AI tools: shotfleet skill install now puts the three shotfleet skills where Claude Code, Cursor, Codex, Gemini CLI and GitHub Copilot look for them.
  • The skills are also in a public repo, noloman/shotfleet-skills. In Claude Code you add them as a plugin, and the plugin also starts the shotfleet MCP server.
  • The MCP server gives short answers: the counts, the first 100 problems and the path to the full report. Before, a big report could be 67,000 characters. Long runs send progress, and run skips your config’s hooks unless you ask for them.
  • iOS: a simulator that stops answering now costs 60 seconds instead of 300, and the next run replaces it with a fresh one. Only shotfleet’s own simulators are ever deleted.
  • When no simulator answers, the message gives you the exact command to shut down shotfleet’s own simulators. It no longer tells you to restart your Mac.
  • Text recognition copes better with a busy Mac. It tries again when the macOS text reader quits without an answer, and it waits when macOS starts preparing the reader in the middle of a check.
  • All nine demo clips are on See it work: from doctor and init to catching the wrong language, store rules, export and CI.

0.1.3, 2026-10-05

  • On Android with Maestro 2.7.0 or newer, shotfleet reads each screenshot’s text straight from the app instead of from the pixels, so it’s exact in every script.
  • The first time macOS prepares its text reader, check waits for it, up to 6 minutes, instead of switching to the slower Tesseract reader after 90 seconds. If macOS still doesn’t answer, it tells you what to do.
  • run warns you when your Mac is short of memory or already swapping hard. capacity = "off" in the config turns the warning off.
  • Every release now stays at its own download address, like https://shotfleet.com/download/0.1.3/shotfleet-macos-arm64.tar.gz, and those files never change.
  • A new page, See it work, with the first clips and my dated list of the real runs behind what this site says.
