# Changelog

## Unreleased

## 0.1.3 (2026-10-05)
- **Site: "See it work" page (/demo):** the first two feature clips (doctor, init) with captions, and a dated evidence list of the release gates, the macOS runs and the real apps run so far, each line backed by a claims row; linked from the home and docs navigation.
- **Text recognition waits for its first compile:** `check` keeps waiting past 90 s while macOS's `ANECompilerService` is using the CPU (up to 6 minutes) instead of dropping to Tesseract; when macOS still does not answer it says what happened and what to do (wait and re-run, close heavy apps, install Tesseract), and says in the output when the fallback reader was used. Catalan, Croatian, Hungarian, Slovak and Slovenian screens are judged by language detection on every macOS, like on macOS 15. Not tested: a real cold compile under load, macOS 13.
- **Memory warning and Maestro deny list:** `run` prints a warning when the Mac is short of memory or already swapping hard (config `capacity = "warn"`, the default; `"off"` silences it). It only warns: the run, the number of devices and the exit codes are unchanged. `run` also stops before booting devices for a Maestro version proven bad (none is today; untested versions still only warn). `tools/latest-maestro.py` downloads only when a new release tag appears.
- **Internal tool `tools/selftest.sh`:** one script a person runs on any Mac (`sh selftest.sh --download`) that installs the release into a throwaway folder, runs `--version`, `doctor` and `check`, prints one PASS/FAIL block and deletes the folder. Not part of the product.
- **Terms and home page: CI keys:** they now say a `SHOTFLEET_KEY` is checked online on every run (no 30-day offline limit; a refunded key stops as soon as a run reaches Gumroad). Wording only; the code is unchanged.
- **Android reads each screenshot's text from the app** with Maestro 2.7.0 or newer (a marker step after every screenshot makes Maestro save the UI hierarchy), exact in every script instead of OCR; `check.json` says per screenshot whether the evidence was `hierarchy` or `ocr`. Older Maestro, and screenshots from other tools, keep reading pixels. Fixture e2e on Maestro 2.11.0: 8 of 8 screenshots read from the hierarchy.
- **Permanent download URLs:** from the next release on, each release (and the earlier ones kept in the release archive) also stays at `https://shotfleet.com/download/<version>/` (for example `/download/0.1.2/shotfleet-macos-arm64.tar.gz`, its `.sha256` and the `.pkg`), and those files never change. The install line and `/download/VERSION` still give the latest.

## 0.1.2 (2026-10-05)
- **`--json` covers every report:** with several reports (several device types, both platforms, Play phone and tablet sets) the one JSON document merges screenshots, problems and notes and adds `reports`, one `{report, problems}` each. With one report nothing changes.
- **The free-tier message says why and how to choose:** when `run` is limited to 2 languages it now says that no valid licence was found, why a `SHOTFLEET_KEY` was not accepted, and that `--locales a,b` picks the two. Wording only; exit codes and who is licensed are unchanged.
- **`check` takes a flat folder:** `shotfleet check shots/ --locale en` checks a folder of PNGs with no `<locale>/` level (a hand-made single-language set); before, it failed with "no screenshots found". Without `--locale` the error says the language is needed and shows the example. The `<locale>/` layouts and exit codes are unchanged.
- **`check` names stale language folders:** a note says when a language folder is not from this run (for example an old `ja` left from an earlier run) instead of quietly checking it with the rest.
- **Android below API 33 is refused up front:** a `system_image` in the config, or an existing emulator, older than API 33 now stops `run` before the emulator boots, with the reason (language switching needs Android 13), the install command and the config key to set. Before, it booted for 1 to 5 minutes and then failed at the first language. API 33 and newer is unchanged.
- **Older Xcode, default iPhone type:** when the config sets no `device_type` and your Xcode has no iPhone 17 Pro Max, `run` uses the newest `iPhone N Pro Max` it finds (same screenshot size) instead of failing. A `device_type` you set is never changed. Tested with simulated Xcode lists only, not on an Xcode without the 17.
- **`init` and the app path:** `init` says in one line when the app build is outside the project folder, so the config holds an absolute or `~/` path and cannot be committed as is. A relative path in the config is resolved from the config's folder, and `run.json` records the clean path. Old configs with an absolute path work as before.
- **Kotlin Multiplatform hint:** `init` now adds that the Xcode build fails with "cannot find X in scope" unless both the debug and the release XCFramework were built first. Text only.
- **Licence in CI, documented:** README, the docs page and the skill now say plainly that a `SHOTFLEET_KEY` run counts as licensed when Gumroad cannot be reached, with no offline limit for a CI key, so an outage hides a refunded key until a run reaches Gumroad. An activated Mac still checks weekly and has the 30-day limit. Behaviour unchanged.
- **Release engineering (not user visible):** the release is published by a script that checks the files, the version and a rollback target before and after, and the build installs only pinned, hash-checked inputs.

## 0.1.1 (2026-10-05)
- **Build for macOS 13 or later:** the release folder is built from a standalone Python (python-build-standalone 3.14.2 via uv, its own Mach-O files at macOS 11.0, the declared minimum is macOS 13) and the OCR helper with `swiftc -target arm64-apple-macos13.0`, so its Mach-O files need macOS 11 or 13 instead of the build host's 27.0, measured with `tools/macho-minos.py`; after the release the live 0.1.1 was run on GitHub's Apple-silicon macOS 14.8.9 and 15.7.9 runners (install, `shotfleet --version`, `doctor` to the end, `check` on two sample screenshots); not run on macOS 13 or 26.0 to 26.2. `packaging/build.sh` takes `PYTHON=<interpreter>` (default `python3`, the old recipe). `research/limits-platform-reach-2026-10-05.md`.
- **First-run friction:** a plain `doctor` no longer offers the ~600 MB fix plan (a loop variable shadowed `--fix`); `doctor` names an Xcode that is installed but not selected, prints per-platform "still needs" lines and Java and no-Homebrew hints; `init` warns when Maestro is missing and explains `<scheme>`; `activate --help` says where the key is and that activation needs internet once; `install.sh` has a clearer PATH hint and next-step wording. `research/limits-first-run-2026-10-05.md`.
- **Refunds:** `site/public/terms.html` has the unconditional 14-day refund wording matching the Gumroad page, says a refund ends the licence and has a VAT and timing line; a buyer whose key Gumroad disabled after a full refund is told so; a non-JSON 200 answer (captive portal) counts as offline with the 30-day grace. Owner runbook in `docs/refund-runbook.md`, notes in `research/refund-process-2026-10-05.md`.
- **Capture reliability:** simulators that booted before a wedged one are cleaned up; `run_guarded` no longer hangs when a helper keeps the output pipe open; a per-device-set lock (fails open if /tmp is not writable) and a SIGHUP handler; an iOS retry with no answering simulator, or an emulator stopping mid-run, keeps earlier results and exits 1 (was exit 2 and no `run.json`); Android clears `raw/<locale>` before a run and a stuck `adb emu kill` no longer skips stopping the others. `research/limits-capture-reliability-2026-10-05.md`.
- **`check` says "could not read" instead of "blank":** when Tesseract or `--ocr-command` (the fallback when macOS text recognition is stuck) finds no text on a screenshot whose pixels are not flat, it is a note and the language is unverified, not a problem that fails the run (seen on a real Arabic Android screenshot, 2026-10-05). Also: a screenshot macOS read before it hung keeps that read; `[expect]` texts on an unreadable screenshot are unverified, not missing; without `--app` Tesseract-read screens get a note that their language was not checked; an app's own "isn't responding" text is not taken for an Android system dialog. `research/limits-check-quality-2026-10-05.md` lists what remains.
- **Found by running real apps** (wger Flutter, the obytes Expo template, kotlinconf-app Compose, Rocket.Chat bare React Native; iOS and Android; `research/frameworks.md` sections 15 to 17):
  - `check` flags a blank screenshot (an app that paints its first frame after the flow's wait: Flutter debug builds, Compose), and `run` captures that language again once, then reports it.
  - `run` warns up front when you ask for a language the app only half translates; a standalone `check <out>` reads the same translation files as the run.
  - `init`: a bare React Native app that depends on the `expo` package is React Native, `app/i18n/locales/*.json` is found, notes for Flutter (`"Title.*"` for merged labels) and Compose, `ARCHS=arm64` in the suggested `xcodebuild` (Xcode 27), a starter flow that waits for text.
  - A selector written as `Self-hosted.*` or `.*Register` has the text inside the wildcard translated; `Not Now` is a system button.
  - `stall_s` (default 900): a run with no new screenshot for that long (a hung simulator or flow) is stopped and retried; before, one hung Maestro kept a 19-language run alive for hours.
- **Flutter and merged labels:** a selector written as `Self-hosted.*` or `.*Register` now has the text inside the wildcard translated (Flutter merges a row's texts into one label with a newline, so a plain selector cannot match); `Not Now` (iOS "Save Password?") is a system button and stays English. Run on real apps for the first time: wger (Flutter), the obytes template (Expo) and kotlinconf-app (Compose), iOS and Android (`research/frameworks.md` section 15).
- **What the macOS 14 and 15 runs showed:** the same Catalan screenshot is skipped on macOS 14.8.9 ("macOS can't read the script of ca") and judged "looks like 'en'" on 15.7.9, because older macOS reads fewer languages; the README and docs say the 33 languages are the macOS 27 number (`research/limits-catalan-check-macos-2026-10-05.md`).
- **iOS 27 on one simulator:** one simulator and one language ran with 0 problems in 78 s (Maestro 2.0.10, 2026-10-05); four simulators at once has not been tried on iOS 27. `runtime` defaults to the newest installed one, so the README and docs tell you to pin a tested runtime (`research/xcode-27-ios27-attempt-2026-10-05.md`).
- **Docs say what is tested:** README and docs have the line `Built for macOS 13 or later on Apple silicon; tested on macOS 27.`, an update line, a licence section in the docs, what a free-tier `run` prints and which two languages it keeps, and the Xcode and Maestro versions that were run.

## 0.1.0 (2026-10-05)
First release: `run` (one English Maestro flow, every language, parallel simulators/emulators), `check` (any
screenshots: language, copies, missing screens, store rules; free), `export` (fastlane deliver/supply folders),
`init`, `doctor`, `mcp`. Reads String Catalogs, .strings/.stringsdict, Android resources, Compose Multiplatform,
and Flutter/React Native/.NET/Unity translation files.

- **CrossfitTracker passes on Maestro 2.11.0:** iOS (iPhone 17 Pro Max), Android phone and Android tablet, 19 languages each, 76 screenshots each, 0 problems, same app (55ad0975, 1.6.2) and flows as the 2.0.10 regression. 9 of 19 iOS languages needed shotfleet's own retry because two of four parallel simulators did not start their XCTest driver within 240 s; whether 2.0.10 does the same at four simulators was not measured. Timings are not comparable (loaded Mac). Recorded in `research/maestro-2-11.md`, `STATUS.md`, `docs/compat.md`.
- **Two more claims softened:** the home page says fastlane snapshot is "open source and built for that" instead of "free" (a third-party fact that can change), and the privacy page says Gumroad passes me the order details, which can include name, email and country, instead of asserting what I receive before a sale exists. C038 and C086 are `fixed`; 46 of 126 claims were still not green on that day.
- **Wording that promised more than was shown:** the README heading no longer says "any tool" (only fastlane snapshot/screengrab, plain folders and `raw/` are tested), the unreachable-Next story says it was `run`, not `check`, that found it, the pages no longer say shotfleet "works alongside" ButterKit and AppScreens (never tried), and the price line promises the outcome (first 100 buyers pay $29) instead of an automatic discount code that does not exist yet. Claims C013, C031, C037 and C056 are now `fixed` by wording; 48 of 126 claims were still not green on that day.
- **Android `[inputs.<locale>]` works on Maestro 2.11.0:** it sets `MAESTRO_DEVICE_UDID` to the emulator's serial and the per-language typed values (German "Jürgen Müller", Japanese "田中太郎") showed up in the screenshots (device run, one emulator, de then ja; two emulators at once and Arabic not run). Maestro 2.0.10 doesn't define the variable, so there Android still types the `[inputs]` defaults. README, docs.html, `references/config.md` and the note `run` prints say so.
- **Maestro 2.11.0 works and is tested:** it only lets `takeScreenshot` write inside its own artifact folder, so the first real run (2026-10-03) captured nothing. Flows now name screenshots relative to Maestro's working directory and shotfleet moves them into `raw/<locale>/` afterwards (both Maestro layouts; the live screen-text capture watches Maestro 2.11's folder too). Fixture e2e on a Mac: 2.11.0 iOS 36/36 and Android 29/29, 2.0.10 iOS 36/36 and Android 29/29. `MAESTRO_TESTED` is now `("2.0.10", "2.11.0")`, `doctor --fix` installs 2.11.0, and the "run refuses Maestro 2.11 and newer" stopgap is removed. Details and the load during the runs: `research/maestro-2-11.md`.
- **Android on Linux uses fewer emulators on a small machine:** `run` now caps the emulator count at half the cores and a third of the free memory in GB (one on a 2-core, 7 GB machine), and says so, instead of booting two that make Android show "Process system isn't responding" over every screenshot. Linux only; macOS is unchanged. The 2-cores-and-3-GB-per-emulator figure rests on one measurement (docs/linux.md) and is unchecked on a 4-core machine.
- **Polar and Lemon Squeezy code removed:** shotfleet is sold through Gumroad only. The Polar licence path (`polar_post`, `polar_valid`, `is_polar_key`, the `polar` store in the saved licence) and the Lemon Squeezy one (`licence_api`, `ls_ours`, the `SHOTFLEET_LICENCE_API` setting) and their tests are gone; no Polar key was ever sold and no Lemon Squeezy key unlocked anything (no product id was set), so nothing that exists stops working. `shotfleet activate` now refuses a key that is not a Gumroad key (four groups of 8) without any network call; a saved licence from an older store is refused with a message to activate the Gumroad key, and `shotfleet deactivate` removes it. Gumroad keys are unchanged.
- **Site:** the round-2 critique and the SEO audit worked through (statuses in `research/site-critique-2.md` and `research/seo-audit.md`): dark-theme pennant and check-mark contrast, 44 px footer, docs and zoom targets, scroll cues on the comparison table, print, no `unsafe-inline` in the style CSP, favicon.ico and apple-touch-icon, sitemap `lastmod`, "not on sale yet" notes that `go-live.sh` removes, and `tests/test_site_audit.py`.
- **Site claims proven in tests:** `tests/test_claims_site.py`, `tests/browser_site.cjs` (Chromium, `/api` stubbed) and more checks in `site/worker.test.mjs` now cover the prices, Apple silicon and Java prerequisites, internal links, what the worker stores and refuses, the 404 page and the signup, contact and counter scripts (claims C002, C033, C042, C077 to C084, C087, C088, C101, C104). The privacy page now says contact messages keep your country and that a removal can take a minute to reach every Cloudflare location.
- **E1 result, run 6:** one emulator fails like two (Maestro cannot find the localized Next button on the Linux runner), so two emulators on 2 vCPUs is not the cause; recorded in `docs/linux.md`, `STATUS.md` and `docs/agent-tasks/05`.
- **Android emulators that fail to start now explain themselves:** each emulator's output is kept in `<tmp>/shotfleet-emulator-logs/`; shotfleet stops at once, with the exit code and the log tail, when the emulator process exits (before, a dead emulator looked like a 600 s hang: "emulators did not boot in time"); a real timeout shows the log tails and the likely cause (no usable `/dev/kvm` on Linux, else memory and CPU); and a full disk is named with its fix (the emulator wants 12 GB free). Found by experiment E1 on a GitHub runner.
- **`doctor --fix` and Google's new Android CLI:** Google's newest command-line tools turned `sdkmanager` into a shim for their Android CLI. Two consequences are handled. It refuses to unpack into an SDK folder whose path contains `..` ("Illegal entry path escaping destination directory"), so every SDK path is now normalised (found on a GitHub runner, where the workspace path has `..`). And it reports usage data to Google unless told `--no-metrics`, which `sdkmanager` itself rejects, so package installs now go through `android --no-metrics --sdk=ROOT sdk install` when that program is present, and through plain `sdkmanager` otherwise.
- **Agent tasks:** `docs/agent-tasks/` holds seven self-contained prompts for what needs a Mac or a KVM Linux machine, and why each is open. `tools/watch-upstream.sh` runs the Maestro and Apple-size watchers locally.
- **Apple size watch:** `tools/apple-specs-watch.py` compares every screenshot size on Apple's specification page with the table `check` uses. First run found four landscape sizes of old devices (960x600, 1136x600 for the 3.5" and 4" iPhones, 2048x1496 and 1024x748 for the 9.7" iPad) that `check` would have called wrong; they are now accepted.
- **Tests:** `tests/test_claims_unit.py` proves five more claims in the register (free-tier cap and licence reach both platform runs, the Gumroad and Polar licence answers, hook variables and exit codes, a translated caption over an English UI) and adds init checks for every framework and archive kind; no change to `shotfleet.py`.
- **`check` knows the iPhone Duo screenshot sizes** (outer 1398x2034, inner 2007x2853; Apple opens uploads later this year). A Duo-only set still needs a 6.9" or 6.5" iPhone set.
- **Maestro watch:** `tools/latest-maestro.py` fetches the newest stable Maestro release and checks it against what shotfleet relies on, failing if something is gone; a compatible newer version is reported as "needs a real run", never as tested. `tools/watch-upstream.sh` runs this and the Apple size check together on your machine; the two GitHub workflows for them are manual-only (this repo runs its checks locally).
- **Compatibility:** `tools/maestro-compat.py` checks any Maestro against what shotfleet relies on, without a device (2.0.10 and the newest, 2.11.0, both pass); tar extraction passes an explicit filter (Python 3.12 deprecates the default, 3.14 changes it); the Linux CI job also runs Python 3.13 with deprecation warnings as errors.
- **`doctor --fix`:** downloads what `doctor` found missing after one question (`--yes` skips it): Maestro pinned by SHA-256 (2.0.10 when this was written; the pin is 2.11.0 now),
  a Java 21 runtime (checksum from Adoptium) and Google's Android command-line tools plus the SDK pieces. Never `sudo`, no shell
  files or PATH edits, no Xcode; `SSL_CERT_FILE` is honoured for proxies. Maestro from `~/.shotfleet` is used before the one on the PATH.
- **Frameworks:** `init` in a Flutter, React Native, Expo, Capacitor, .NET MAUI or Kotlin Multiplatform project folder finds
  the build where that framework puts it, writes the `strings` line for the translation files it finds and prints the
  framework's own build commands; EAS `.tar.gz` and `.zip` builds are unpacked by `init`. Translations written as objects
  in code (`.ts`, `.js`) and Android `<string-array>` are read.
- **Build hook:** `init` in a framework project leaves a commented `[hooks] before_run` with that framework's build command.
- **Flows:** `launchApp` options may be written on one line, `- launchApp: { permissions: { all: allow } }`.
- **Linux:** `check` reads screenshots with Tesseract where macOS text recognition does not exist (and Tesseract now gets one
  thread per process: four screenshots took 73 s, now 0.5 s), `doctor` reports Tesseract and KVM, the Android SDK and image
  logic knows Linux folders and the host CPU's architecture, and `.strings`, `.stringsdict` and `Info.plist` are read in
  Python when `plutil` and `PlistBuddy` are absent. Android `run` on a Linux emulator is coded but untried.
- **Store:** sales and licences go through Gumroad (Polar was dropped: its payout provider asks a Dutch resident for a KvK). A Gumroad key has 3 activations; refusing a key never uses one, activating again on the same Mac counts nothing, and refunded, charged-back or disputed purchases stop working at the next weekly check (a won dispute keeps working). `deactivate` cannot give an activation back, so moving to a fourth Mac means an email. Polar and Lemon Squeezy keys still worked then (changed later: see the Polar and Lemon Squeezy bullet above).
- **Simpler setup:** only the build is required in `shotfleet.toml`; bundle id, package and flow are read or defaulted.
  One config and one flow serve iOS and Android (an `appId:` header is set per build), `shotfleet run` needs no
  arguments, `init` takes several builds, and a typo or wrong type in the config is refused with a one-line message.
- **Licence (changed later: Polar was dropped, see the Polar bullet above):** Polar added as a store (keys start with `SHOTFLEET-`), alongside Lemon Squeezy and Gumroad. `run` without a
  licence captures up to 2 languages; `export` and all languages need a key.
- **Extending:** `[hooks]` (before/after run and export), `[overrides.<locale>]` for what to tap in one language,
  `shotfleet-<name>` plugins on the PATH, `--no-hooks`.
- **Setup help:** `doctor` finds Homebrew's keg-only Java and passes `JAVA_HOME` to Maestro, checks Java 17+, and says what
  to do next; `check` handles a fastlane folder holding both stores when given `--app`.
- **Readers:** a locale folder beats a short namespace file name (`locales/en/app.json`), i18next namespaces that share a
  key both survive, gettext `.po` files use their `Language:` header and plural forms, an empty accessibility tree falls
  back to OCR, and partly translated languages are reported instead of skipped silently.
- **Site:** redesigned; signup asks what you build with.
