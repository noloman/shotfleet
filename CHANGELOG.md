# Changelog

## Unreleased
- **`scrollUntilVisible` with a plain text is translated:** `element: "Settings"` stayed in English; only `element: { text: "Settings" }` was translated. Both are now, in the block form and on one line.
- **A moment for the screen to settle before each screenshot:** a splash or a sliding sheet could still be on screen when the picture was taken. `run` now puts a `waitForAnimationToEnd` step in front of every `takeScreenshot`, with a limit of 1 second (`settle_ms` in the config changes it, `0` turns it off). It can't help when an app holds one splash image for seconds; wait for a text of your first real screen for that. Not run on a device yet.
- **Language codes that differ between platforms:** asking for `zh-Hans` on an Android app that ships `zh-CN` (or the reverse, `zh-Hant` and `zh-TW`, `pt` and `pt-BR`) used to end with "none of those languages are in the app". `run` now uses the code the app ships and says so. When two codes would fit (`pt` with both `pt-BR` and `pt-PT`) it doesn't guess and names the codes the app has.
- **"iOS driver not ready in time" is a device failure:** Maestro's driver can take too long on a simulator's first boot on a busy Mac. The language's error now says so instead of "no result", and it is retried once like the other device failures.
- **A stuck pool simulator is replaced under the same name:** it already was; now there is a test for it, the message says "same name, new id", and the README says what that means for scripts that look simulators up by name or by id.
- **`check --app` on a Flutter build tells you what to pass:** "This is a Flutter build: pass --strings 'lib/l10n/*.arb'" (React Native, MAUI and Unity get their usual folder). And `--strings` together with `--app` now works: the translation files are used and the build still decides the store rules. Before, `--app` made shotfleet look only in the build and stop.
- **`check` on the parent folder of a multi-device run:** when the app runs on iPad and no device folder has a 13-inch iPad set, the iPad column now says `missing`, every device's check lists it as a problem, and the exit code and the problem count agree. It used to show `-`, print "0 problem(s)" and exit 1. A one-device run folder (`out/`) now also applies the iPad rule; before, `check out` silently skipped it because it looked like one device of several. `run.json` records `multi_device` so `check` doesn't have to guess.
- **Optional `key` in `[expect.<screenshot>]`:** `key = "benchmarks_title"` requires the app's own text for that string key, in each screenshot's language, to be on screen. It catches a green run that captured the wrong screen. Off unless you add it.
- **`doctor` says which iOS runtime `run` will use:** with iOS 26.4 and 27.0 installed it said "ok iOS Simulator runtime iOS 27.0". It now names the one `run` uses, and why when a newer one is skipped (or that your config sets it).
- **Android on a Maestro without a screen hierarchy says so with the result:** below Maestro 2.7.0 (2.0.10 is one) `check` reads Android text by OCR. `run` prints that at the start and again before the check, and suggests Maestro 2.11.0.

## 0.1.7 (2026-10-08)
- **A store coverage table at the end of `check`:** one row per language and one column per device class (App Store: iPhone 6.9", iPhone 6.5", iPad 13"; Google Play: phone, 7" tablet, 10" tablet), each cell `ok`, `missing`, `too many` or `wrong size`, with plain lines such as `ja: iPad 13" missing (the App Store needs it because your app runs on iPad)`. It is in the console, `index.html`, `check.json` and `--json` (`coverage`) and changes no exit code.
- **`check --compare <earlier folder>`:** lists per language and screen what is new, removed or changed since an earlier shotfleet output or fastlane folder (image hashes, plus the text lines added and removed where both sides have the app's `.texts.json`). Report only, no text recognition, exit code unchanged; it is in `check.json` as `compare`.
- **`export --print-upload`:** prints the `fastlane deliver` or `fastlane supply` command that uploads the exported screenshots. It only prints; shotfleet still never uploads. The README and docs now also show the `asc screenshots upload` route.
- **`run` skips iOS 27.0 simulators by default:** they froze at boot in some of my runs. With no `runtime` in the config, `run` uses the newest other installed runtime and says which one and why in one line; if iOS 27.0 is the only one, it uses it and warns. `shotfleet doctor` warns in that case too and explains `runtime = "..."`. A runtime you set is always used. The list of runtimes to skip is one small table in the code.
- **A warning when the Mac is very busy:** when swap is 90% full or more, macOS reports critical memory pressure, or the load is far above the number of cores, `run` prints one plain warning ("this Mac is very busy; simulators may stop answering") and suggests fewer parallel devices. It checks again before a retry and between Android rounds, warns once per run, never refuses to run, and `capacity = "off"` silences it.
- **No more simulator calls without a time limit:** listing, creating and deleting simulators (and `doctor`'s runtime and device-type lookups) had none, and a Mac under heavy load could hang there. They now end with a message that says the Mac is probably too busy.
- **`run --retry-failed`:** reruns only the languages that failed in this config's last `run.json`. The ones that passed stay as they were and stay listed in `run.json`, and the tries of the retried languages add up in `attempts`.
- **Only device failures are retried by themselves:** a language is retried once when the simulator or emulator failed (not answering, boot timeout, Maestro dying before it reported), not when the flow or the app failed (element not found, wrong number of screenshots): that would fail the same way again. A blank screenshot (the app painted its first frame late) is also captured again once, then reported. `run` says which languages it did not retry. Android results now carry `attempts` too.
- **The device test for running your own XCUITest tests passed:** the site no longer says it hasn't.
- **No more "no usable release date" warning on Linux:** the Linux build and the `check` Docker image now bake in their build date like the Mac build does, so a frozen Linux `shotfleet` no longer prints that warning on every start.
- **Export hooks get `SHOTFLEET_PLATFORM` on iOS too:** `run` now writes `platform` into `run.json` for iOS runs (only Android runs did), so `before_export` and `after_export` no longer see it empty.
- **The MCP `run` summary says when the free tier cut the languages:** a short `note` field, for example "Free tier: captured 2 of 3 languages (de, ja)", so an agent doesn't have to guess why some are missing.
- **Guides have a feed:** https://shotfleet.com/guides/feed.xml (Atom), linked from the guides page and every guide.
- **The site's server no longer has a signup route** (there is no signup form). Messages, the forget form and visit counts work as before; stored data is untouched.

## 0.1.6 (2026-10-06)
- **`check` works on fastlane supply's own file names:** supply puts the locale in every name (`1_de-DE.png`, `1_en-US.png`), so `check` said every language was missing every other language's screenshots. It now ignores the folder's own locale at the end of a name when it matches screens, but only when every file in that folder ends in it, so two different screens can't get mixed up. On a real 15-language Play set the 15 false "missing" lines are gone.
- **A Russian screen is no longer "Kazakh":** macOS's language detection read a Russian screen full of English job titles as 99% Kazakh, and `check` reported it. Now, when detection names a close Cyrillic neighbour (Russian, Ukrainian, Belarusian, Bulgarian, Kazakh and a few more) and the screen matches the app's own strings for the expected language and no other, that's a pass. A Ukrainian screen in the Russian folder is still caught when the app's Ukrainian strings show it.
- **A failed language now says where it stopped:** under the `FAIL` line, `run` names the step Maestro failed on (with its selector, as Maestro's log has it), the path to the failure screenshot, and up to 12 texts that were on that screen. The texts come from the screen hierarchy Maestro saves with the failure; only when there isn't one does shotfleet read the screenshot, once, and it skips that while macOS text recognition is busy.
- **iPad landscape taps that miss get a plain explanation:** in iOS landscape Maestro still taps at portrait coordinates, so on a real iPad run every tap after `setOrientation: LANDSCAPE_LEFT` landed 344 points off. When the log shows exactly that (a portrait-sized frame and a tap on the element's portrait position), `run` says so in one line: capture iPad in portrait, or open the screen with a launch argument or deep link.
- **No more memory note on plain failures:** "this Mac was short of memory ..." showed up even when a flow simply failed an assertion. It now only shows when a failure is actually `Unknown error` or `Unable to clear state`.
- **Use your existing XCUITest screenshot tests (iOS):** a `[capture]` table in the config (instead of `flow`) makes `run` build your test bundle once with your own `build` command, then run `xcodebuild test-without-building` on several simulators at once, one language each. shotfleet sets each simulator's language itself (Xcode ignores `-testLanguage` with a prebuilt bundle), and collects `XCTAttachment` screenshots from the result bundle and fastlane `SnapshotHelper` files from its cache folder (made if missing; fastlane's `language.txt` and friends are moved aside and put back). A language that saved no screenshots, or misses a screen, fails even when the test passed. Same pool, retry, hung-simulator handling, `check` and `export` as a Maestro run; paid like `run`, 2 languages free. `run --no-build` skips the build, `init --capture` writes the table, and `doctor` stops asking for Maestro for iOS when the config has one. iOS only; the device test (`tools/fixture-byoc-e2e.sh`) passed on iOS 26.4 simulators.
- **5 activations per key:** the licence is for up to 3 of your Macs, and from 0.1.6 a key can be activated 5 times (0.1.5 and earlier still stop at 3), so a reinstall no longer eats one of your 3 Macs. If you run out, email hello@shotfleet.com for a reset. The site, terms, docs, README, `llms.txt` and the skill now say "use it on up to 3 of your Macs; there are spare activations for reinstalls".
- **A year of updates, for real:** a key covers every shotfleet version released within a year of the purchase, a calendar year: up to the same date a year later (29 February counts to 1 March). It compares Gumroad's sale date with the release date frozen into each build's code, never your Mac's clock, and a build without a release date isn't treated as covered. A version released later runs as the free tier with your key and says which versions your key covers; the versions you have keep working. The sale date is saved with the licence, so it works offline too. No renewal is on sale yet: email hello@shotfleet.com. Builds from October 2026 work for every buyer so far.
- **CI keys no longer pass just because Gumroad is unreachable:** a `SHOTFLEET_KEY` is still checked online on every run and still uses no activation, but with Gumroad unreachable it now counts only on a machine where it passed a check in the last 30 days (shotfleet notes a hash of the key and the date there, never the key). On a fresh runner during an outage it is refused with a message saying so: `export` stops and `run` captures 2 languages. Before, any well-formed key passed whenever Gumroad was blocked.
- **The licence server can't be swapped in a released build:** `SHOTFLEET_GUMROAD_API` (for tests) is now ignored by released builds.
- **Licence: activating can't burn an activation any more:** shotfleet saves your key on this Mac before it asks Gumroad to count the activation, so an unwritable folder fails first (nothing is used), and a lost answer on flaky Wi-Fi is remembered: run `shotfleet activate` again and it won't count twice. A key that covers no version like this one is refused before anything is used. If others activate at the very same moment and take the last slot, you're told and nothing is saved.
- **Licence: sturdier files and odd replies:** the licence files are written whole or not at all (no half-written file after a crash or two runs at once), and an unreadable one is re-checked online instead of costing an activation. A strange answer from the network (a proxy's junk, a cut-off reply, an empty 403/407/429, a login page) now says "can't reach the licence server" instead of a Python error or "invalid key". A licence call gives up after 20 seconds.
- **Licence: refusals stick, and clock mishaps heal:** a refund, charge-back or disabled key found at the weekly check is remembered, so blocking Gumroad afterwards doesn't bring the licence back (also for `SHOTFLEET_KEY`). A Mac whose clock was fast during a check re-checks online and carries on. A read-only licence file no longer stops `run`. The MCP server picks up a new activation without a restart.
- **`SHOTFLEET_KEY` is a gate in CI:** if it's refused or can't be checked, `run` now stops (exit 2) instead of going green on 2 languages. If this Mac has its own activation, that is used instead, with a warning. On hosted runners, cache `~/Library/Application Support/shotfleet/ci-checked.json` between jobs to keep the 30-day offline grace.
- **Site: HSTS:** every page tells browsers to use HTTPS for six months (no subdomains, no preload).
- **MCP: no command from the config runs unless you pass `hooks: true`:** `run` used to skip only `[hooks]`; the `[capture]` build (a shell command) ran anyway. Now a config with a `[capture]` build, `[ios] simctl` or `[android] shell` commands is refused over MCP without `hooks: true`, with a line naming them. On the command line nothing changes.
- **MCP: `check` no longer takes `ocr_command`:** it ran any program it was given, from a tool marked read-only. Use `--ocr-command` in your terminal. `check` is no longer marked read-only either, since it writes its report.
- **Language codes are checked before they become folder names:** a translation file saying its language is `../../x` could make `run` delete a folder outside the output folder. Languages from translation files, builds, the config, `--locales` and MCP must now be letters, digits, `-` and `_`; a bad one is skipped with a note (files) or refused (config, `--locales`). The config's `package` and `avd` names are checked too.
- **Safer lock files in /tmp:** the device and text-recognition lock files are no longer opened through a symlink, are made readable only by you, and are skipped (the run goes on) when the file belongs to someone else or isn't a plain file. Runs from your other terminals still take turns as before.
- **Release script:** `packaging/publish.sh` only accepts a manifest version made of digits and two dots.

## 0.1.5 (2026-10-06)
- **`check` with Tesseract or `--ocr-command` no longer burns minutes of CPU:** matching each screen's text against the app's strings built a fresh regex for every string, every language, every screenshot, which on 220 screenshots cost 3 to 5 minutes of CPU on top of the reading itself. It now looks for the plain text first and only runs the regex when it's there. Same verdicts, a couple of hundred times faster.
- **README: honest check timing:** the old "about 25 seconds" could not be reproduced. On 220 real screenshots it now says 57 to 86 seconds with text recognition warmed up, measured on 2026-10-06.
- **`doctor` tells Homebrew users to run `brew upgrade`:** when a new version is out, a copy installed with Homebrew now shows `brew upgrade --cask noloman/tap/shotfleet` instead of the install line.
- **No more false "isn't an App Store screenshot size" on Android screenshots:** a plain folder of language folders with no `--app` was always judged as App Store screenshots, so 72 Android screenshots gave 72 size problems. Now fastlane's folder layout or your build decides first. If neither does, the sizes do: all App Store sizes means App Store rules, no App Store size means Google Play rules. If it's a mix, each screenshot is judged against both stores (a problem only when neither store takes it), and a note says so.
- **The HTML report works with screen readers:** the page has a language, every screenshot has alt text (language, screen and verdict), and problems are marked "⚠ problem" in words, not just with a red border. Contrast now passes WCAG AA in light and dark mode, links show a keyboard focus ring, and the headings go in order. In light mode it looks the same as before.
- **Homebrew:** `brew install noloman/tap/shotfleet` installs the same signed, notarized build, as a cask in my tap [noloman/homebrew-tap](https://github.com/noloman/homebrew-tap) (Homebrew's docs say proprietary, binary-only programs go in casks). It doesn't install Maestro or Java; `shotfleet doctor --fix` does. The install line stays the main way. README, docs and `llms.txt` say so. `tools/bump-homebrew.sh <version> <tap checkout>` points the cask at a new release and prints the diff; it never pushes.
- **Site: free licences and invoices:** open-source maintainers and students can email hello@shotfleet.com for a 100%-off code, and Gumroad makes an invoice from your receipt (no purchase orders). On the home page, the docs, the terms and `llms.txt`.
- **`check` no longer fails after a long wait for macOS text recognition:** on a quiet Mac, macOS once spent about 40 minutes compiling its text model, and `check` gave up with exit 2 after 6 minutes, or stopped on a compile error. Now all of a check's waiting on text recognition shares one 8-minute budget. When it runs out (or macOS keeps failing) and Tesseract isn't installed, `check` still finishes: screens with the app's own text are judged from it, store sizes and missing screens are checked, and the screens nobody read are marked "not verified (macOS text recognition was busy)" in the output, at the top of the report and in a new `unverified` list in `--json`. Unread screens that are identical across languages get a note, not a copy problem, since games and no-text screens are identical on purpose. `doctor`'s text-recognition lines say the same: no restart needed. They don't change the exit code; `check --strict` makes them exit 1. The fix is to run check again later or install Tesseract (`brew install tesseract`). No restart needed. With Tesseract installed nothing changes: it takes over as before.
- **Concurrent checks take turns warming up text recognition:** two shotfleet checks on one Mac (another session, CI and your own run) no longer start macOS's text model compile at the same time. One warms it up, the other prints "another shotfleet is preparing macOS text recognition; waiting" and then reads in parallel as usual. The wait counts against the same 8 minutes, and the lock goes away by itself when its process ends.
- **`check` on Linux and in CI, in Docker (built, not published yet):** I built a `check` image for amd64 and arm64 (the compiled program, Tesseract with 34 common languages, and aapt2) and a GitHub Action, `noloman/shotfleet-check-action`, that runs it on `ubuntu-latest`. I did not publish either one, so `ghcr.io/noloman/shotfleet-check` and the Action are not there for you to use yet; an earlier version of this line said they shipped, which was wrong. On the 72-screenshot Android set the image gave the Mac's verdict with `--app`. In the image, `run` and `export` stop with one line saying the image only runs `check`. `packaging/docker-check.sh` is the script that builds the image and will push it when I publish it (by hand), and the Linux build now checks PyInstaller's wheel hashes too.
- **`check` works on fastlane screengrab output:** screengrab ends every file name in a timestamp (`01Home_1773697012807.png`), different in every language, so `check` said every language was missing every other language's screens. It now ignores that timestamp when it matches screens, and keeps the real names in the report. If one language has the same screen twice with two timestamps, that's a problem. On a real 8-language screengrab set the 8 false "missing" lines are gone.
- **`check` finds your app build by itself:** without `--app` it looks where `init` looks (your Xcode project's newest Debug simulator build in DerivedData, your Gradle debug APK, or a Flutter/React Native project's translation files), picks the one for the store your folder is for, and says in one line which build it used, or that it found none.
- **Clearer alpha channel problem:** a PNG with an alpha channel but no see-through pixel (XCUITest and design tools save these) was reported as "has transparency". It now says "has an alpha channel, though every pixel is opaque". Both stay problems, because both stores' rules forbid the alpha channel itself, and both lines now say how to fix it (`sips -s format jpeg in.png --out out.jpg`).
- **Docs: fastlane and Paparazzi:** a ready-made Fastfile lane (`snapshot` or `screengrab`, then `shotfleet check`, which fails the lane before the upload), a note that fastlane users don't need `export`, and how to check Paparazzi, Roborazzi or Compose preview renders (a folder per language, or `--locale` for one). README, docs, the home page, the alternatives page and `llms.txt` now say `run` needs Maestro and `check` doesn't.
- **install.sh no longer touches your real `shotfleet` link from a test install:** an install with `HOME` set to another folder used to overwrite `/opt/homebrew/bin/shotfleet`. It now links inside that `HOME` (`~/.local/bin`). `SHOTFLEET_BIN_DIR` picks the folder yourself.
- **New logo:** three phones fanned like a hand of cards, the front one yellow with a check (one flow, many devices, every screenshot checked). Replaces the flag in the favicon, the Apple touch icon, every page's header, the link preview image and the Gumroad icon, thumbnail and covers. `marketing/logo/build.py` rebuilds them all.
- **No "Ready for Apple Intelligence" banner over your screenshots:** on an iOS 26 simulator that banner popped up a few minutes after the first boot and landed on top of a Turkish screenshot in one of my runs. shotfleet now tells the simulator it was already shown, right after boot. On Android, heads-up notification banners are now switched off too (demo mode only hid the notification icons).
- **`check` flags that banner when it reads the picture:** if the text reader finds "Ready for Apple Intelligence" in the top fifth of a screenshot, that is now a problem. It only works where `check` reads the pixels (Android, or screenshots you bring yourself). In an iOS run `check` reads the app's own texts instead, and the banner is not in there, so the fix above is what keeps it out.
- **Release scripts: a locked screen no longer looks like a lost notarization profile:** shotfleet now uses its own notarytool profile, `ShotfleetNotary`. macOS locks that profile about 5 minutes after the screen locks, and notarytool then says the profile is missing. The check now says to unlock the Mac and run again, and runs right before each upload to Apple. `packaging/release.sh` keeps the Mac awake while it builds and notarizes.
- **Memory warning names the real device count:** when shotfleet had already cut the run to 2 devices because of memory pressure, the warning still said "this run still uses 4". It now says how many this run really uses.

## 0.1.4 (2026-10-06)
- **Site: all nine demo clips on /demo:** doctor, init, a run on iPhone, a run on Android, catching the wrong language, checking screenshots you already have, store rules, export to fastlane, and CI. Real recordings on the fixture apps, with subtitles; sped-up parts are labelled.
- **Text recognition retries a helper that quit:** on a very busy Mac the macOS text reader sometimes quits without an answer while it is still getting ready. `check` used to stop right there and blame the compile; now it tries again every 10 seconds within the same time limit.
- **`check` is faster on a folder in a busy place:** to tell whether a folder is one device of a multi-device run, `check` listed every entry next to it. In a big folder like the system temp folder (68,000 entries on my Mac) that cost about 15 s per check. It now looks for two `run.json` files instead. Same answer.
- **Site: plain, informal English:** I rewrote the website in my own voice, in simple English, and added a short "What it saves you" section to the home page. No facts or prices changed.
- **The skills are in a public repo:** [noloman/shotfleet-skills](https://github.com/noloman/shotfleet-skills) holds the three skills as a Claude Code plugin with its own marketplace (`/plugin marketplace add noloman/shotfleet-skills`, then `/plugin install shotfleet@shotfleet`; the plugin also starts `shotfleet mcp`) and works with `gh skill install noloman/shotfleet-skills --all`. README and the docs page say so. The skill text now points at the docs page instead of the README, and no longer mentions running from source. `tools/sync-public-skills.sh <checkout>` copies `skill/` there at each release, sets the plugin version and prints the diff; it never pushes.
- **`shotfleet skill install` reaches every big AI coding agent:** it now writes the three skills to `~/.claude/skills` (Claude Code, Cursor) and to `~/.agents/skills` (Codex, Gemini CLI, GitHub Copilot, Cursor), and prints one line per folder. With `--project` it writes `./.claude/skills` and `./.agents/skills`. Each folder keeps skills that are already there unless you pass `--force`. `--dir <folder>` still writes only that folder.
- **Docs: other agents do load skills:** the skills README used to say Codex, Cursor and Gemini CLI read only a project instructions file, not skill folders. That is no longer true. README, the docs page, the skill's config reference, `llms.txt` and the AGENTS.md block now say which agent reads which folder. The AGENTS.md block no longer points at `skill/shotfleet/` (only in the source repo, buyers don't have it); it points at the installed skill and `shotfleet skill install --project`.
- **Docs: the licence key and AI agents:** README and the docs page now say to run `shotfleet activate` once on your Mac so your agent uses the CLI without seeing the key, to use the `SHOTFLEET_KEY` secret in CI, and not to pass the key with `claude mcp add --env` (it ends up in plain text in `~/.claude.json`). Wording only.
- **MCP: short answers.** `check` and `run` now answer with counts, the first 100 problems and notes, and the path to the full `check.json`. Before, you got the whole report, and a big one (40 languages x 10 screens is about 67,000 characters) got moved to a file by Claude Code. Pass `full: true` for the whole thing.
- **MCP: `check` takes `report`,** the folder for `check.json` and `index.html`, like `--report` on the command line.
- **MCP: `run` skips your config's `[hooks]` unless you pass `hooks: true`.** On the command line nothing changes.
- **MCP: progress during long calls.** If your client asks for progress, the server sends the last output line every 30 seconds, so a long `run` doesn't look stuck.
- **MCP: the tools say what they do.** `check` and `doctor` are marked read-only, `run` is marked as one that changes things, and the descriptions say how long `run` can take.
- **MCP: honest protocol version.** The server used to answer with whatever version the client asked for. Now it only says 2025-11-25 or 2025-06-18, the ones it really speaks.
- **"No simulator answers any more" says what to do without a restart:** it gives the exact `xcrun simctl shutdown <UDID>` for shotfleet's own simulators (before, it suggested restarting the Mac or `xcrun simctl shutdown all`, which also stops your other simulators) and says the next run replaces the stuck ones.
- **iOS: a simulator that stopped answering is replaced at the next run:** shotfleet remembers it (`~/.shotfleet/hung-simulators/<UDID>`) and the next run deletes it and creates a fresh one under the same name before booting. Only shotfleet's own pool simulators (`shotfleet-...-<n>`) are ever deleted. In the 0.1.3 release tests the same two pool simulators hung in three runs in a row.
- **iOS: a simulator that stops answering costs 60 s, not 300 s:** before the run shotfleet no longer sends `simctl terminate` (uninstalling the app stops it, as Maestro's own clear-state does), and the uninstall, now the first call on each simulator, gives up after 60 s. In the 0.1.3 release test each stuck simulator held the run for 300 s.
- **iOS: the app is installed on every simulator at once:** a simulator that stops answering now costs one timeout for the whole pool instead of one each in turn (in the 0.1.2 release test, five stuck simulators cost 1500 s of the iOS step's 1872 s); a failed one is still replaced in pool order.
- **Memory warning wording:** it said "running 1 device at once instead of 4" although the run still used 4 (the warning only warns); it now says 1 would be safer and that the run still uses 4.
- **Text recognition waits for a compile mid-check too:** when macOS starts compiling its text-reading model while `check` is already reading screenshots (seen on a Mac at load 800), each read now waits for that compile (up to 6 minutes, only while `ANECompilerService` is using the CPU) like the warm-up does, instead of failing with "text recognition hung twice" on a Mac without Tesseract.

## 0.1.3 (2026-10-05)
- **Site: "See it work" page (/demo):** the first two feature clips (doctor, init) with captions, and a dated evidence list of the release gates, the macOS runs and the real apps run so far, each line backed by a claims row; linked from the home and docs navigation.
